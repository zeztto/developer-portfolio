# 개발·검증 방식

[README](../README.md) · [대표 사례](case-studies.md)

## 요구사항부터 확인

어떤 입력으로 어떤 결과가 저장되고 보이는지 먼저 정합니다. 화면의 표현, API 계약, 데이터 모델, 실제 운영 상태를 함께 살피며, 알 수 없는 정보는 추정값으로 채우지 않습니다.

## AI와 협업

AI는 구현과 조사·검토를 돕는 도구로 사용합니다. 역할별로 책임과 수정 경로를 구분하고, 변경 결과를 독립적으로 검토하는 흐름을 구성합니다. 외부 agent workflow에서 출발한 확장 작업은 upstream 기반임을 구분하며, 타인의 프레임워크·모델·소스를 독자 개발로 소개하지 않습니다.

개발 workflow 확장 작업은 [Everything Claude Code / ECC](https://github.com/affaan-m/ECC)를 기반으로 합니다. 도구별 adapter·역할과 규칙·설치 및 검증 절차를 확장한 경험이며, upstream 자체를 만든 이력이나 upstream 기여 실적으로 표현하지 않습니다.

작업 지시에는 목표, 허용 경로, 보존할 항목, 입력·출력 계약, 검증 방법을 담습니다. handoff에는 완료 사실뿐 아니라 실패·보류·미검증 범위를 남깁니다. 이는 작업 방식에 대한 설명이지 AI 결과의 무오류를 주장하는 표현은 아닙니다.

## 상태를 구분하는 검증

| 단계 | 확인하는 것 | 이 단계만으로 주장하지 않는 것 |
| --- | --- | --- |
| 코드·타입·정적 검사 | 계약·구현·구문·타입 | 실제 사용자 동작 |
| 단위·회귀 테스트 | 성공·실패·경계 조건 | 모든 통합과 제품 품질 |
| 격리 환경 | 저장·재조회, 변경과 부작용 | 운영 환경의 반영 |
| 브라우저·native UI | 실제 입력과 탐색, 화면의 표시 | 모든 장치·브라우저 지원 |
| 배포 확인 | 일치하는 commit·CI·운영 버전 | 기능 전체의 정상 동작 |
| 운영 smoke | 지정한 경로의 실제 결과 | 전체 서비스의 무결성·가용성 |

## 데이터와 운영 환경 보존

- 기존 로컬 변경과 원본 자료를 먼저 확인하고 관련 없는 내용을 되돌리지 않습니다.
- 운영 데이터의 쓰기 테스트와 조회 검증을 구분합니다. 파괴적 검증은 승인된 격리 환경을 사용합니다.
- 공유 환경에서는 변경 대상과 다른 서비스를 구분하고, 되돌릴 수 있는 방법을 준비합니다.
- 비밀번호·token·OAuth 값·DB·원문 로그·관리자 이미지를 공개 PR에 넣지 않습니다.

## 사용자 화면 확인

작은 화면과 세로형 화면에서 탐색·입력·저장 흐름을 확인합니다. 한국어 줄바꿈·가로 넘침·겹침을 실제 렌더링에서 살피고, 저장 요청 성공뿐 아니라 재진입 후 값과 공개 화면을 확인합니다. native 앱에서는 창·편집·파일 흐름을 별도로 확인합니다.

## 릴리스와 보안 유지관리

기능 변경은 task branch·PR·회귀 검사·리뷰를 거칩니다. 운영 반영은 승인과 배포 결과를 확인한 뒤 구분해 보고합니다. 문서나 저장소의 버전만 올라갔다고 운영 배포를 완료했다고 표현하지 않습니다.

의존성 점검에서는 현재 lockfile과 공식 권고·수정판을 대조합니다. 패치 설치, advisory 철회, 버전 범위 변경, 예외 허용은 서로 다른 사건으로 기록합니다. 읽기 전용 점검과 자동 적용·merge·배포도 구분합니다.

## 이 저장소의 검사

이 저장소는 Markdown·JSON 문서 중심이며 애플리케이션 설치나 서버 실행이 필요 없습니다. Node.js의 built-in API만으로 검사합니다.

```sh
node scripts/catalog.mjs --check
node scripts/check-docs.mjs
```

문서 검사는 상대 링크, 데이터 스키마, 프로젝트·기술 색인의 일치, 버전과 기본 공개 안전성을 확인합니다. 외부 사이트의 모든 기능과 과거 이력을 증명하지는 않습니다.

공개 목록을 새로 수집할 때만 다음 명령을 실행합니다. 결과 diff와 공개 범위를 다시 검토한 뒤 반영합니다.

```sh
node scripts/catalog.mjs --refresh
```
